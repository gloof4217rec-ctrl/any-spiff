# spiff → Transient Sculptor: разбор и план реализации

Источник: [официальный мануал oeksound spiff](https://oeksound.com/manuals/spiff/)
(разделы 1–5). Диапазоны значений в мануале не указаны — там, где ниже написано
«предлагается», это наша трактовка, а не факт из мануала.

## 1. Что делает spiff

> «Spiff is an adaptive transient processor that cuts or boosts only the frequencies
> that make up the transient material, keeping the rest of the audio signal intact.»

Ключевые свойства:

- Обрабатывается **не весь сигнал**, а только частотные области, в которых есть
  транзиентная информация. Если в бочке на 300 Hz нет атаки, spiff её не тронет.
- Два режима: **cut** (по умолчанию, «убрать клики/щелчки») и **boost** (подчеркнуть
  атаку).
- **Не зависит от входного уровня**: результат определяется параметром depth, а не
  громкостью входа (внутренняя нормализация детектора).
- Изначально оптимизировался под вокал: минимальные артефакты, «хирургическое»
  удаление кликов, вдохов, щелчков от компрессии/эквализации.
- Рекомендации по месту в цепи: **cut** — последним инсертом; **boost** — в начале,
  до компрессоров/лимитеров/сатураторов.

## 2. Параметры (по секциям)

### 2.1. Main

| Параметр | Смысл | Предлагаемый диапазон / дефолт |
| --- | --- | --- |
| **Depth** | Глубина обработки: больше depth → сильнее вырезание/подъём. Не зависит от входного уровня. | 0…100 %, дефолт 0 (spiff «выключен» по глубине) |
| **Sensitivity** | Порог/чувствительность детектора транзиентов. Выше → ловится больше транзиентов (в т.ч. тихие). Ниже → только громкие. | 0…100 %, дефолт ~50 |
| **Sharpness** | Ширина (Q) каждой отдельной cut/boost-области. Меньше — натуральнее на перкуссии; больше — лучше для гармонических источников (пиано). | 0…100 %, дефолт ~50 |
| **Decay** | Время восстановления после cut/boost. 0 — обрабатывается только самое начало транзиента; больше — захватывается «хвост». Значения < 5 звучат наиболее натурально. | 0…10 (в мануале «lower than 5»), дефолт 0…2 |
| **Decay LF/HF** | Разница во времени восстановления между низом и верхом. Ниже центра → низ decays дольше; выше центра → верх дольше. В центре — одинаково по спектру. | 0…10, центр = 5, дефолт 5 |

### 2.2. Stereo (для стерео-инстанса)

| Параметр | Смысл | Предлагаемый диапазон / дефолт |
| --- | --- | --- |
| **Stereo mode** | L/R или Mid/Side — какие каналы контролируются независимо. | enum: `Left/Right`, `Mid/Side`, дефолт L/R |
| **Stereo link** | 100 % — sidechain-сигналы объединяются, одинаковое reduction в оба канала. 0 % — «два моно-инстанса» (dual mono). | 0…100 %, дефолт 100 |
| **Balance** | Распределение обработки между каналами. 100/0 — только left (mid), центр — 100/100 оба, 0/100 — только right (side). Крайние значения меняют подпись окна на «left only / right only / mid only / side only». | 0…200 % (100/100 в центре), дефолт 100/100 |

### 2.3. Output

| Параметр | Смысл | Предлагаемый диапазон / дефолт |
| --- | --- | --- |
| **Mix** | Dry/wet. 100 % — только обработанный, 0 % — только исходный. Работает и в delta-режиме (смешивает dry с delta). | 0…100 %, дефолт 100 |
| **Trim** | Make-up gain только для wet-части (компенсация изменения уровня). | −24…+24 dB, дефолт 0 |
| **Delta** | Выдаёт разницу wet−dry — слышно, что именно плагин делает. Ключевой инструмент настройки. | bool, дефолт off |
| **Bypass** | Мягкий bypass для A/B без щелчков. Плагин **продолжает считать** — CPU не экономится. | bool, дефолт off |

### 2.4. Advanced

| Параметр | Смысл | Предлагаемый набор |
| --- | --- | --- |
| **Resolution** | Временнóе разрешение: как часто обновляются внутренние настройки и насколько точно определяется момент транзиента. | enum: Low / Medium / High (дорого по CPU) |
| **Oversample** | Считает reduction-фильтр в более высоком разрешении: глаже АЧХ, точнее на низах. | enum: Off / 2x / 4x / 8x |
| **Window** | Компромисс время/частота. Short — минимальный ringing, ловит очень быстрые транзиенты, хуже низы (хорош для клик-ремувала). Long — больше ringing, глаже, для сложных полифонических источников (пиано). Medium — универсальный. | enum: Short / Medium / Long, дефолт Medium |
| **Phase mode** | Linear phase — рекомендуется для хирургических cut'ов (особенно с Short window), но возможен слышимый pre-ring на низах. Minimum phase — без pre-ring, натуральнее для boost, чуть тяжелее по CPU. | enum: Linear / Minimum, дефолт Linear |

### 2.5. Частотный граф (кривая чувствительности)

Это **не эквалайзер**, а вес обработки — «sidechain EQ» для детектора:

- **5 полос**: три параметрические (в мануале показаны как red / yellow / purple) плюс
  **lo cut** и **hi cut**.
- Параметрические полосы: типы **parametric / low shelf / high shelf / tilt shelf**,
  регулируются freq, gain (вес обработки), Q (Q меняется модификатором: Cmd/Ctrl + drag).
- lo/hi cut: частота среза + **slope в дБ/окт** (ниже/выше этих частот плагин игнорирует
  материал).
- Полосу можно **bypass** (двойной клик по узлу или тумблер в панели полосы).
- Мультивыделение: рамкой или Shift+клик.
- **Band listen** — мониторинг delta-сигнала только в области выбранной полосы
  (быстрый поиск нужной частоты); временно включается Alt + drag узла.
- **Reduction graph** — синяя/красная (cut/boost) визуализация фактического reduction
  по частоте; настраиваемый диапазон отображения (precise ↔ large).

### 2.6. Toolbar / прочее (не DSP, но влияет на UX)

- Preset menu (factory + user presets, теги, поиск, «save as default», open from file).
- Undo/redo (своя история, отдельная для A и B).
- A/B switch + A→B copy.
- Help: интерактивные туториалы, мануал, шорткаты, about.
- Config: disable OpenGL, disable tooltip, auto band listen, use dry signal with band
  listen, display range of reduction graph.

## 3. Архитектура DSP (наш план)

spiff — адаптивный спектральный процессор; «в лоб» через обычный транзиент-дизайнер
(две огибающие на широкополосном сигнале) это не повторить, потому что нужна
частотная избирательность. Предлагаемая схема:

```
in ──► [анализ STFT] ──► [детектор транзиентов по бинам] ──► [веса полос]
                                    │
                                    ▼
                          [gain-кривая (complex/real)]
                                    │
in ──► [задержка/выравнивание] ──► [применение gain] ──► [mix/trim/delta] ──► out
```

Компоненты:

1. **STFT-анализ** с окном Hann, FFT 1024/2048, hop = N/4 (75 % overlap).
   Параметр *Window* меняет длину FFT (Short 512–1024, Medium 2048, Long 4096).
2. **Детектор транзиентов на бин**: две огибающие — быстрая (`fast`) и медленная
   (`slow`). «Транзиентность» = `fast / (slow + eps)`; превышение над порогом,
   задаваемым *Sensitivity*, даёт 0…1 «transient amount» на бин.
3. **Decay** задаёт release медленной огибающей (и время спада gain'а); *Decay LF/HF*
   интерполирует release по log-частоте между низом и верхом.
4. **Кривая чувствительности**: 5-полосный EQ (RBJ biquads / shelf-фильтры) применяется
   к sidechain-сигналу (копия входа), а не к аудио. Его magnitude response по бинам =
   вес `w[f]`, 0…1 (с учётом lo/hi cut).
5. **Gain**: `g[f] = depth * transientAmount[f] * w[f]`, знак — cut или boost.
   *Sharpness* управляет Q спектрального сглаживания gain-кривой по частоте
   (чем выше — тем уже/резче области обработки).
6. **Phase mode**:
   - *Linear*: gain применяется как вещественная симметричная функция в STFT-домене
     (даёт pre-ring, зато точные cut'ы) — обязательна компенсация задержки для dry/delta.
   - *Minimum*: из gain-кривой строится min-phase FIR (cepstral method) и применяется
     свёрткой; natural для boost.
7. **Stereo**: L/R — независимые детекторы; M/S — матрица перед детектором.
   *Link* смешивает sidechain-огибающие: `env = lerp(envL, envR, link)`.
   *Balance* — независимые множители глубины для каналов.
8. **Delta** = wet − dry (с выравниванием задержки), **Mix** смешивает dry/wet,
   **Trim** — только к wet.
9. **Oversample** — пересчёт gain-кривой / FFT на повышенной частоте (2x/4x/8x).
10. **Resolution** — как часто пересчитываются веса и огибающие (каждый блок / каждый
    hop / прореженно), влияет на CPU.

Realtime-требования (см. `CLAUDE.md`): все буферы, FFT-объекты и окна аллоцируются в
`prepareToPlay`; в `processBlock` — только копирование и арифметика. Никаких
`std::vector::push_back`, строк и локов в аудио-потоке.

## 5. Порядок работ

1. **MVP**: параметры Main/Output + STFT-детектор + cut, delta, mix, trim.
   Проверить на вокале с кликами, замерить CPU, прогнать `ctest` и pluginval.
2. Граф чувствительности: 5 полос, lo/hi cut, band listen, reduction-график.
3. Advanced: window/resolution/oversample/phase mode.
4. Stereo: link/balance, M/S.
5. UX: A/B, undo/redo, пресеты, туториалы.
